# 给 Codex 的工作交接 / 可以直接复制的任务

## 当前工程

请先阅读 `README.md`、`docs/API.md`、`docs/PRD.md` 和 `data/skills.json`。本项目是一个已可运行的零依赖 Node.js + 原生 JS 的 Skill 中文发现平台，而不是一个空项目。

目前只用本地目录；不要未经同意改成新的框架，也不要先加用户系统、数据库、收费模型或自动下载安装。

当前正式目录为 65 条；8 条学生候选预览是其中已有条目的 staging 深度审核版本。专题集合已按新手任务重新精选，不应把所有开发或平台专用工具重新加入默认入口。

## 第一批建议交给 Codex 的任务（不要全部一起做）

### 任务 A：把真实 SKILL.md 变成待审核的中文展示数据

> 请在我当前的 EasySkillShow_MVP 项目里，根据 `docs/API.md` 的数据契约，帮我研究 5 个真实 Skill。每个 Skill 首先确认原始来源和对应 `SKILL.md`，阅读其关键说明、依赖和脚本。然后生成一个 `staging/真实slug.json` 文件，结构与 `staging/codex-output.example.json` 一致。
>
> 中文文案面向不了解 Skill 的大学生，一句话说清楚它能帮用户完成什么，补充 2～3 个典型场景、用户输入和可能输出、使用条件与能力边界。不要编造安装量、Stars、作者、截图、兼容性或“已实测”等结论。区分“源文档明确写到”“基于文档推断”“仍需测试”。
>
> 先运行 `npm run check:data`，再使用 `npm run import:skill -- staging/xxx.json` 进行干运行检查；**暂时不要执行 --write**，把待审核条目交给我确认。不要运行未知脚本或安装未知仓库。

推荐优先处理的候选方向：对大学生实用的文档、学习、前端设计、科研与自动化 Skill。不要自动选安全审计有警告的 Skill 运行。

### 任务 B：真实效果素材

> 请从已有精选 Skill 中选择 1 个文档处理和 1 个网页设计 Skill，先确定测试目标、工具和依赖，得到我确认后再安装或执行其脚本。保留输入、环境、输出文件、日志、截图、源引用，并把每份素材的许可和验证状态记录在项目文档。不能把模型想象的 UI 图片当成真实运行截图。

### 任务 C：搜索改进

> 保持一级页/二级页结构，补齐更有针对性的中文关键词词库，并用可复现的测试案例验证相关性。不要只靠引入大模型在线搜索，先改进本地词匹配逻辑。完成后列出测试通过率及仍不支持的查询。

### 任务 D：Codex 查询版

> 在另一个独立目录创建一个 `easy-skillshow-finder/SKILL.md`，让 Codex 按用户自然语言任务查询本地 API `/api/v1/skills?q=...`，获取详情并用中文说明功能、限制和来源。没有找到的 Skill 必须明说，不得编造。默认仅查询，不执行安装。写明 localhost 服务器必须运行的前置条件，并提供 3 个测试问答。

## 交付检查

1. 本地服务能运行，且浏览器 UI 没被破坏。
2. `npm run check:data` 无报错。
3. 新增记录有真实 URL，旧有 ID 不被覆盖。
4. `reviewStatus` 保持 `pending`，待我确认后升级为 `source-checked`。
5. 不使用未授权的素材，不绕过安全警告。

## 首次在 Windows 浏览器里检查（必做）

请在项目根目录执行 `npm test` 和 `npm start`，使用 Chrome 或 Edge 分别以 1366×768 和 390×844 的视口打开网站。检查：

- 首页所有卡片能正确显示，没有文字重叠、按钮溢出和横向滚动；
- 搜索「制作 PPT」后能进入 `pptx` 详情；
- 在「功能介绍 / 使用示例 / 安装方式 / 限制与来源」之间切换正常；

- 分类、排序、收藏、浏览器刷新后收藏仍在；
- 页面跳转和返回列表不丢失使用体验。

若发现问题，先修复响应式样式与交互，不要自行扩大 MVP 范围。
