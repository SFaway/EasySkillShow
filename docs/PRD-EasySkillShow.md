# EasySkillShow 产品需求文档

> 文档版本：Lean PRD v1.0  
> 更新日期：2026-10-18  
> 产品阶段：本地 MVP，准备开展目标用户测试

## 1. 产品摘要

EasySkillShow 是一个面向中文用户的 Skill 发现与理解平台。第一阶段重点服务对 Skill 不太熟悉、希望用 Skill 改善学习或工作的大学生，帮助他们从“我想完成什么”出发，在 3 分钟内找到一个合适的 Skill，并理解它能做什么、如何使用以及有什么限制。

产品不替代 Codex 等 AI 工具，也不是一个安装后独立运行的软件。它负责把分散、偏技术化的 Skill 信息整理成可搜索、可比较、可追溯的中文目录；用户仍需在支持 Skill 的 AI 工具中使用对应能力。

## 3. 背景

Skill 的原始资料通常以英文 `SKILL.md`、GitHub 仓库说明或开发者文档呈现。初次接触的用户需要先理解专业术语、判断使用条件，再确认来源和安装方式。这让“找到一个可能有用的 Skill”和“敢于实际使用它”之间存在较高的理解成本。

当前 EasySkillShow v0.2 已建立本地精选目录，收录 65 条来源可追溯的 Skill，并提供中文搜索、固定分类、精选场景、收藏、简明版与详细版介绍、示意性使用案例、来源与统计信息。另有 8 条 staging 深度审核稿，对应正式目录中的已有条目，不重复计数。现阶段还没有真实用户测试，因此“中文分层介绍能够明显降低理解成本”仍是需要验证的产品假设，而不是已经证明的结论。

## 4. 产品目标

### 4.1 目标

让第一次接触 Skill 的大学生，无需先理解复杂术语，也能从自己的学习或工作任务出发，快速找到并正确理解一个合适的 Skill。

这项能力将帮助 EasySkillShow 验证其核心价值：平台的优势不是收录数量最多，而是让普通用户更容易完成“发现—理解—判断是否使用”的全过程。

### 4.2 第一轮关键结果

在 6～10 名符合目标用户特征的大学生测试中：

1. 至少 80% 的参与者能在 3 分钟内找到一个与指定任务匹配的 Skill。
2. 至少 80% 的参与者能正确说明该 Skill 的主要用途、一个使用条件和一个能力边界。
3. 至少 80% 的参与者能找到原始来源，并分辨“来源已核对”“示意性案例”和“经过实测”三种状态。

以上数字是首轮验证目标，不是现有实验结果。完成测试后应根据真实数据调整。

## 5. 目标用户与市场分段

### 核心分段：任务驱动、但不熟悉 Skill 的大学生

这类用户已经在学习或工作中使用 ChatGPT、Codex 等 AI 工具，但不了解 Skill 生态，也不知道该搜索什么名称。他们通常从具体任务出发，例如整理课程资料、制作汇报、阅读论文、检查简历、排查代码问题或设计网页。

他们的主要限制包括：

- 不熟悉英文名称和开发者术语。
- 难以判断 Skill 与独立软件、提示词或插件的区别。
- 不容易确认运行条件、安全风险和真实来源。
- 没有耐心阅读很长的原始文档，只愿意在确认有用后再查看细节。

第一版不优先服务需要全量索引、自动化安装或高级开发接口的专业开发者。这些需求可以在核心价值验证后再评估。

## 6. 价值主张

### 6.1 面向核心用户的六部分价值主张

- **谁：** 想用 AI 改善学习或工作的大学生，但对 Skill 不熟悉。
- **为什么：** 他们知道自己想完成的任务，却不知道应该找哪个 Skill，也无法快速判断候选项是否适用。
- **使用产品前：** 依赖搜索引擎、GitHub、skills.sh 或他人推荐，在英文说明和技术术语中反复查找；容易只看名称、热度或安装量做决定。
- **EasySkillShow 如何帮助：** 用中文任务词搜索或按场景浏览，通过简明版快速理解用途，再通过详细版查看步骤、前置条件、产物、限制和原始来源。
- **使用产品后：** 用户能更快缩小候选范围，知道下一步该怎么使用，并在安装前发现不适用条件或潜在风险。
- **替代方案：** GitHub 和 skills.sh 提供更广的来源与热度信息，搜索引擎和 AI 对话也能给出推荐；EasySkillShow 的差异是面向新手的中文分层说明、固定分类、事实状态标注和人工审核流程。

**价值主张陈述：** 当大学生想用 AI 完成一个具体任务时，EasySkillShow 帮助他们在 3 分钟内找到并理解合适的 Skill。平台先解释“对你有什么用”，再提供使用方法、限制和可追溯来源，减少因术语和信息分散造成的选择困难。

## 7. 解决方案

### 7.1 核心使用流程

1. 用户从任务关键词、一级分类或“大学生常用”等精选场景进入目录。
2. 用户浏览紧凑的 Skill 卡片，先比较中文名称、一句话用途、分类和来源状态。
3. 用户进入详情页，默认阅读简明版，在 15～30 秒内判断是否相关。
4. 用户需要进一步判断时，切换到详细版，查看工作流程、环境要求、使用步骤、预期产物和能力边界。
5. 用户查看原作者页面和安装命令；平台只负责展示和复制，不自动执行第三方脚本。

### 7.2 第一版关键功能

1. **按任务发现 Skill：** 支持中文名称、用途、别名和场景词搜索，并提供固定一级分类、按需展开的二级任务与跨分类精选集合。
2. **分层中文介绍：** 列表和简明版优先回答“能做什么、适合谁、典型用途”；详细版回答“怎么用、需要什么、会得到什么、有哪些限制”。
3. **真实状态标注：** 区分原始文档事实、合理推断和未经实测的示例。来源已核对不等于安全或功能已经测试。
4. **来源与选择依据：** 展示原始仓库、Skill 文件、采集时间、仓库 Stars，以及能够可靠获得的安装量。缺失数据不展示，不用其他数字代替。
5. **低成本浏览体验：** 支持收藏、排序、紧凑列表、可收缩目录和窄屏使用；用户无需登录或配置 API Key。
6. **受控内容维护：** 新内容先进入 staging，经过数据校验、导入预检查和人工审核后才能进入正式目录；导入过程保留备份。

### 7.3 技术与数据原则

- 第一版使用 Node.js 18+、本地 JSON 和只读本地接口，不要求用户连接外部 API。
- 浏览器不保存 GitHub、skills.sh 或其他外部服务令牌。
- 平台不自动下载、安装或运行第三方 Skill 代码。
- 当前目录是人工精选样本，不宣称覆盖 skills.sh 全部内容。

### 7.4 假设与待验证问题

- **假设：** 用户的主要障碍是看不懂和不会选，而不是没有使用 Skill 的需求。
- **假设：** 从 65 条正式记录中精选出的场景集合足以完成第一轮发现与理解测试；目录规模本身不代表体验质量。
- **待验证：** 用户更常从搜索、分类还是精选场景开始寻找。
- **待验证：** 简明版是否足以支持第一次判断，以及哪些信息必须提前展示。
- **待验证：** Stars、安装量和审核状态会怎样影响用户信任，是否会造成“热度等于质量”的误解。
- **待验证：** 用户理解 Skill 后，能否顺利转到 Codex 等支持工具中完成安装与使用。

## 8. 发布范围

### 8.1 第一版包含

- 65 条经过来源核对或等待人工审核的正式目录记录，以及不重复计数的 8 条 staging 深度审核稿。
- 面向大学生任务的中文搜索、七个固定一级分类、二级任务和精选集合。
- 列表页、二级详情页、简明/详细切换、示意性案例、收藏和来源信息。
- 本地运行、数据校验、staging 审核和安全导入机制。
- 6～10 名目标用户的可用性测试与原始结果记录。

### 8.2 后续再做

- 根据真实搜索和测试结果调整分类、文案及首页推荐。
- 在内容质量稳定后，分批扩充可靠 Skill，并补充经过验证的真实演示素材。
- 评估服务端同步、在线部署和 Codex 查询 Skill 的必要性。

### 8.3 第一版明确不做

- 不做全量 Skill 搜索引擎或与 skills.sh 比拼收录数量。
- 不做用户登录、社区评论、公开投稿和复杂后台。
- 不做浏览器端实时调用第三方数据接口。
- 不做自动安装、一键运行或对第三方 Skill 的安全背书。
- 不把示意性输入输出包装成真实运行结果。

### 8.4 相对时间安排

- **阶段一：内容和体验收口。** 完成当前目录的一致性检查，修复影响核心流程的问题。
- **阶段二：用户测试。** 邀请 6～10 名目标用户完成统一任务，记录用时、理解正确率和困难点。
- **阶段三：基于证据迭代。** 优先修复阻碍 3 分钟目标的问题，再决定是否扩大收录和上线范围。
