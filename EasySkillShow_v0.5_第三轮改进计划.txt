EasySkillShow v0.5 第三轮产品改进计划
生成日期：2026-10-20

产品目标
缩短“进入任务—浏览候选—打开详情—返回继续选择”的路径，让 119 条目录在不制造信息过载的情况下仍然完整可达。

依据与假设
1. 当前没有真实搜索日志、卡片分类或树测试数据；本轮结论属于信息架构假设，不冒充用户研究。
2. 主要用户仍假设为不了解 Skill 名称、优先按学习或求职任务寻找工具的大学生。
3. 目录适合“任务入口 + 搜索 + 分类/专题”的混合查找，而不是只依赖一个分类树。

实施清单
[x] 任务入口进入结果页后显示任务名称和说明，不再只显示技术分类名。
[x] 结果页显示当前搜索、分类、子分类或专题条件，支持一键重置。
[x] 全目录默认分批展示 20 条，用户主动加载更多，避免一次呈现 119 条。
[x] 详情页返回时保留筛选条件与原来的滚动位置。
[x] 首页展示最近浏览的 Skill，并完全保存在本机浏览器。
[x] 零结果状态提供返回全部目录和任务入口两种恢复方式。
[x] 页面版本同步为 v0.5，并完善移动端布局。
[x] 为分页、最近浏览、任务上下文增加自动化回归测试。
[x] 运行 npm run check 与 npm test。
[x] 浏览器检查任务结果、加载更多、详情返回、最近浏览和移动端。

后续研究
[ ] 用真实大学生做任务入口首击测试，验证六个任务名称是否符合心智模型。
[ ] 收集匿名且明确同意的搜索词样本，检查零结果和词汇不匹配。
[ ] 对分类树进行至少一次开放式卡片分类或树测试后，再决定是否调整正式 taxonomy。
