# 第 10 批中文详情优化对比

## 共同改进

1. 把“云成本优化”和“版本升级”改写为可执行的用户流程，而不是 API 或命令清单。
2. Azure 条目把实际账单、预测、估算节省和最终变更明确分开。
3. Prisma 条目把 SQL 项目与 MongoDB 项目分流，避免把错误迁移路径包装成通用升级。
4. 所有案例都标记为未实测，不声称已读取真实账单、修改依赖或验证数据库。

## azure-cost

- 原文重点：费用查询、预测和优化三条工作流，以及 Cost Management API 的范围、角色和限流规则。
- 优化后：先确认账号范围与只读权限，再查询总账单和成本驱动；预测与历史数据分开；优化建议必须引用实际成本、指标和当前价格，任何删除、降配或购买承诺都需要另行确认。

## prisma-upgrade-v7

- 原文重点：生成器、显式输出、驱动适配器、ESM、`prisma.config.ts`、环境加载、导入路径和移除功能。
- 优化后：先确认确实是 Prisma 6 的 SQL 项目，再分阶段升级；明确 MongoDB 不能走 Prisma 7 SQL 路径，并要求在隔离环境完成生成、类型、连接、迁移和回归测试。

## 证据分层

- 原始 Skill 与直接引用资料明确写出的能力和限制进入 `sourceFacts`。
- 目录定位、适用人群与实施保护进入 `reasonableInferences`。
- 未连接账号、未运行升级和未验证示例的内容进入 `untestedClaims`。
