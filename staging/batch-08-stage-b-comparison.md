# 第 8 批中文详情优化对比

## 共同改进

1. **先讲结果**：把 eval、baseline、compound component 和 hard gate 转成“测试效果、比较基线、组合组件、方案批准后再实施”等用户可理解的动作。
2. **区分建议与执行**：提交信息只输出文本；React 条目先审查再重构；头脑风暴在用户允许时才调研或做原型；Skill 创建先确认测试规模再运行大量评测。
3. **保留平台差异**：Skill Creator 原流程中的 Claude CLI、子代理、Python 和浏览器依赖没有被包装成所有 Agent 都能直接使用的通用能力。
4. **明确未验证状态**：四项案例均标记为演示性，未声称真实创建 Skill、运行基准、读取 Git 仓库、重构 React 或完成需求访谈。

## 逐条变化

### skill-creator

- 原文重点：从意图澄清、Skill 编写到有 Skill/无 Skill 对比、评审页面、迭代和描述触发优化的完整开发循环。
- 优化后：先解释用户会得到什么，再分离“创建”“行为测试”“人工评价”“触发优化”四层；增加模型调用成本、敏感测试数据、Claude 专用脚本和主观评测边界，并与只生成 README 的能力区分。

### caveman-commit

- 原文重点：极短的 Conventional Commits 信息，为什么优先于做了什么，并且只生成文本。
- 优化后：突出绝不执行 Git 写入；说明何时一行足够、何时必须保留安全修复、迁移、回滚和破坏性上下文，并禁止编造 issue、日期和兼容性影响。

### vercel-composition-patterns

- 原文重点：用组合、复合组件、状态提升、Provider 接口和显式变体避免布尔属性膨胀。
- 优化后：加入“先确认 React 版本和调用方，再决定是否值得重构”的决策步骤，明确 React 19 规则不能用于 React 18，并补充类型、行为与可访问性回归测试。

### brainstorming

- 原文重点：用一次一个开放问题理解真实意图，分段回放，复杂项目在批准完整描述前设置实施门禁。
- 优化后：避免包装成所有任务都必须长访谈；明确快速任务可直接执行、用户可跳过问题、临时原型不等于生产实现，并解释何时值得使用视觉伴随。

## 证据分层

- 原始 `SKILL.md` 明确描述的流程和限制写入 `reviewEvidence.sourceFacts`。
- 适用人群、目录定位和安全实施建议写入 `reasonableInferences`。
- 所有未执行的文件创建、评测、Git、React 重构、视觉稿和访谈写入 `untestedClaims`，并保留 `demoStatus=illustrative`。
