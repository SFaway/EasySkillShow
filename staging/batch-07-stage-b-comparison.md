# 第 7 批中文详情优化对比

## 共同改进

1. **先讲用户结果**：把 RLS、context pointer、checkpoint、schema 等术语先翻译成数据库权限、指令入口、人工确认点和接口参数检查。
2. **明确动作权限**：数据库默认只读审查，Agent 文档先展示差异，工作流只写规格，考勤只查本人；审批逐笔确认，飞书幻灯片先规划和预览再写入，不把说明 Skill 写成自动执行工具。
3. **保留真实性**：每条案例都标记为演示性、未实测，安装量与 Stars 说明为页面快照和仓库指标。
4. **暴露来源状态**：`loop-me` 的测试中状态、考勤隐私、数据库生产风险、Agent 行为不确定性、审批高风险写入、云端演示文稿覆盖风险和强风格适配限制均进入页面边界。

## 逐条变化

### supabase-postgres-best-practices

- 原文重点：8 类 Postgres 规则和按影响排序的参考文件。
- 优化后：用“先只读审查，再测试验证，最后才执行迁移”的用户流程解释规则如何使用，并强调静态 SQL 审查不能替代真实执行计划。

### writing-for-agents

- 原文重点：上下文指针、两类负担、信息层级、完成条件、领先词和删减原则。
- 优化后：转换为“何时读取、当前需要看到什么、怎样判断完成、如何避免重复过期”的四个用户问题，并增加前后验证要求。

### loop-me

- 原文重点：用 grilling 访谈把生活循环写成工作流规格。
- 优化后：明确只产出规格、不实施自动化，解释触发、人工检查点和决策摘要，并给出课程截止日期整理的完整示例。

### lark-attendance

- 原文重点：一个个人考勤查询接口、固定内部参数和只读 scope。
- 优化后：突出“只查本人、调用前看 schema、空结果不等于缺勤、考勤属于敏感信息”，避免误解为补卡或管理员工具。

### lark-approval

- 原文重点：路由审批查询与多种处理命令，默认使用用户身份，并根据任务状态错误停止盲目重试。
- 优化后：把只读查询和真实写入拆成两层；同意、拒绝、转交、退回、催办、撤回等动作必须展示准确单据与参数并逐笔确认，同时说明创建审批定义和普通任务不在范围内。

### minimalist-ui

- 原文重点：暖色单色、编辑式字体、Bento 网格、低饱和点缀和一组严格禁止项。
- 优化后：明确它是可调整的风格预设，不是通用设计系统或可用性证明；补充品牌冲突、字体与素材许可、键盘与对比度、减少动态效果和性能验证边界。

### lark-slides

- 原文重点：用飞书 XML 创建和编辑云端幻灯片，要求先规划、写前校验、写后回读，并区分块级修改与整页覆盖。
- 优化后：用“逐页计划—XML 校验—用户确认—云端写入—回读与截图复核”解释完整链路；明确它与本地 PPTX 工具互补，突出整页覆盖、删除、回滚和图片上传的风险。

## 证据分层

- 原文明确能力写入 `reviewEvidence.sourceFacts`。
- 学生项目、实习自查和验证策略写入 `reasonableInferences`。
- 所有未执行的查询、文件修改、自动化、数据库验证、审批操作、网页渲染和云端幻灯片写入都写入 `untestedClaims`，并保留 `demoStatus=illustrative`。
